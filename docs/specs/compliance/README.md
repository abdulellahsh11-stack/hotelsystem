# مواصفات الامتثال — ZATCA وشموس (Spec-Driven)

هذه الوثائق تتبع أسلوب **Spec-Driven Development** (على غرار github/spec-kit):
**مواصفة (Spec) → خطة (Plan) → مهام (Tasks)** — تُكتب المواصفة أولاً،
وتُراجَع، ثم يُبنى الكود وفقها. تكاملان تنظيميّان **لا يحتملان الخطأ**؛
فالمواصفة هي خط الدفاع الأول.

## الملفات
| الملف | الغرض |
|---|---|
| `zatca-phase2.spec.md` | مواصفة تكامل الفوترة الإلكترونية ZATCA المرحلة ٢ (موثّقة رسمياً) |
| `shomoos.spec.md` | مواصفة تكامل تسجيل النزلاء شموس — **بحدود Adapter، وصيغة السلك Placeholder حتى تتوفّر المواصفة الرسمية** |
| `PLAN-AND-TASKS.md` | الخطة التقنية وتقسيم المهام (P0/P1) والاعتماديات ومعايير القبول |

## المبادئ الحاكمة (من `CLAUDE.md`)
1. **مصدر الحقيقة**: ضيوف يملك بيانات الفاتورة والنزيل؛ الجهة الحكومية مستقبِل.
2. **التحقق بالكسر**: لكل حارس اختبارٌ يكسره أولاً قبل الوثوق به.
3. **لا سقوط صامت**: فشل الإرسال يُسجَّل ويُعاد، لا يُبتلع.
4. **الإيديمبوتنسي**: لا إرسالٌ مكرّر يُنتج فاتورةً/تسجيلاً مزدوجاً.
5. **سجلّ تدقيق**: كل إرسال/استجابة يُحفظ خاماً (كما في `payment_events`).
6. **عزل المنشأة**: كل صفٍّ يحمل `client_id` ويُصفّى به.
7. **لا API مُخترَع**: أي حقل/نقطة غير موثّقة رسمياً تُعلَّم `TODO: official spec`.
